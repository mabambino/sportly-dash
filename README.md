# Syncletics

Run your sports club from one place — members, courses, schedule, attendance,
stats, chat, announcements and payments, built for club owners, trainers,
students and parents.

Built with [Lovable](https://lovable.dev) on TanStack Start + React 19 +
Supabase (Lovable Cloud), styled with Tailwind CSS 4 and shadcn/ui.

## Features

- **Dashboard** — live club KPIs, real member-growth chart, upcoming sessions
- **People** — members (with staff "Add member" flow and CSV export), groups,
  courses with flexible per-day weekly schedules, progress log, CSV import
- **Operations** — schedule with RSVP, capacity enforcement and iCal export;
  one-tap tick / cross / clock attendance marking; attendance analytics with
  weekly trends, leaderboard and streaks
- **Money** — member invoices with a server-validated pay flow; revenue
  overview with monthly chart, per-course breakdown, platform fees and
  automatic country tax calculation
- **Growth** — leads and a kanban trial pipeline
- **Communication** — real-time chat, announcements, notifications
- **Settings** — club profile, team role management, dashboard layout

## Development

```sh
bun install
bun run dev
```

Environment variables live in `.env` (Supabase URL and the *publishable* anon
key — safe to expose; row access is enforced with RLS).

## Database migrations

SQL migrations live in `supabase/migrations/`. Committed migration files are
**not applied automatically** — run new ones in the Supabase SQL editor
(Lovable Cloud → Database). In particular, apply
`20260703120000_improvements.sql`, which:

- locks payment updates down to staff and adds the `pay_invoice()` RPC used
  by the member "Pay now" flow,
- adds `course_groups.schedule_slots` for per-day course times,
- adds club tax columns and creates the `leads` table idempotently.

The app degrades gracefully until the migration is applied.

## Architecture notes

- Routes are file-based under `src/routes/` (TanStack Start). See
  `src/routes/README.md` for conventions.
- `src/lib/*.functions.ts` are server functions; admin (service-role)
  operations live only there, never in client code.
- `src/integrations/supabase/` is generated by Lovable — don't edit by hand.
- Payments use a simulated checkout validated server-side; to collect real
  money, plug Stripe into `pay_invoice()` and drive status from webhooks.
